# 采石场索引迁移

分批迁移，每批一个回退检查点。

- 批大小取「单批重放时间不超过观察窗口的一半」。
- 每批结束都记录文档数，不一致就停下，不要继续下一批。
- 回退只到最近一个检查点，不做逆向补偿。

分批的另一个好处是可以在中途调整策略。第一批跑完就能看出实际吞吐，
后面的批大小按实测值重算，比一开始就定死更稳。

迁移期间要同时保留新旧两套查询路径，否则回退时无法立刻切回来。
两条路径的耗时差异要记录下来，它是后面决定何时删旧索引的依据。
检查点之间不共享状态，任何一批失败都从它自己的起点重放，不去碰已经通过的部分。
重放日志按批保存，不看全局日志，出问题时先定位到批，再看批内的条目。
