# 果园笔记

缓存目录是 `build/.orchard-cache`，删掉它会让下一次构建从零开始。
默认并行度是 4，配置项在 `orchard.toml` 里，改成 3 之后磁盘压力明显下降。
超时阈值默认 900 秒，只对单步生效，不覆盖整条流水线。
如果缓存键里带上了环境变量，换一次终端就会全量重建，这一点很容易被忽略。

缓存目录不要放进版本控制，也不要用清理脚本顺手删掉。
它里面的内容是可重建的，但重建的代价是一次完整的全量构建。
判断缓存是否还有用，看目录的修改时间，而不是看它的大小。
缓存与产物的关系是单向的：缓存随时可以删，产物删了就要重新打包一次。
缓存目录的路径在配置里写死，不要用相对路径，工作目录一变就会换个地方重建。
