# 采石场笔记

分片键是 `tenant_id`，不是文档 id，这点在两次迁移里都踩过。
重分片的实际步骤是：先双写，再回填，最后切读。
回填期间新旧分片同时可读，查询会走两遍，延迟翻倍但不至于超时。
切读之后旧分片保留一周再删，留出回退窗口。
分片数不是越多越好，超过 64 之后元数据开销开始显现。

分片键为什么不能用文档 id：查询几乎总是按租户切，用文档 id 会让每次查询都扫全部分片。
改分片键等于重建整套索引，所以它在设计阶段就该定下来，事后再改的成本极高。
回填速度要限流，不限流会把线上查询挤掉，回填本身也会因此被拖得更慢。
分片数量一旦确定就不要频繁调整，每调一次都要重新回填一遍全部数据。
