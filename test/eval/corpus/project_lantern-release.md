# 灯笼 v0.4.2 发布检查清单

四个锚点必须指向同一个版本号，缺一个就不算发布完成：

1. `package.json` 里的 version
2. git tag
3. 远端 tag 与发布说明（说明正文不能为空）
4. 包索引里某个分发标签指向它

回滚步骤写在发布说明的最后一段：先撤回分发标签，再撤 tag。
顺序不能反，标签先撤会让已经安装的人拉到一个不存在的版本。

发布前还要过一遍产物清单，确认打包里没有夹带本地文件。
发布说明面向的是使用者，第一段写「这次改了什么」，不要写实现过程。
版本号只在四个锚点处出现，别的地方都不写版本号，免得又多出一个需要同步的位置。
锚点核对可以脚本化，但发布说明的正文必须由人写。
