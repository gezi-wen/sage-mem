# 果园构建超时排查

构建超时先看两处，顺序不要换：

1. 缓存是否失效。缓存目录被清理或键变了，所有步骤都会重跑，超时只是表象。
2. 并行度是否过高。并行度拉满时磁盘会成为瓶颈，单步耗时反而上升。

判断缓存是否失效有一个便宜的办法：看第一次构建的耗时。如果它和随后的构建几乎一样，
说明缓存从来没生效过，而不是这一次失效了。

并行度的调整要一次只改一项。同时改并行度与超时阈值，事后无法判断哪一项起了作用。
排查的过程记录在构建日志里，只保留最近一次，历史记录随缓存目录一起被清理。
先修缓存再调并行度，顺序反了会把缓存失效的代价算到并行度头上。
两次改动的间隔要留够一次完整构建的时间，否则观察不到效果。
