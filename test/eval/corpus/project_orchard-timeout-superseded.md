# 果园构建超时（旧口径）

⚠️ 已作废：以下结论自 2026-09 起不再适用，现行口径见 project_orchard-timeout.md。

构建超时先看并行度，把并行度降下来，单步耗时就会下降。
缓存不是首要怀疑对象，缓存失效只影响第一次构建，不会让后续构建也超时。

并行度是唯一需要调的项，超时阈值只在并行度调到最低之后还超时的情况下才动。
排查顺序是先并行度、再超时阈值，缓存放在最后，避免在没证据的情况下清缓存。

并行度调到最低仍然超时的情形，当时认为是缓存以外的原因，没有继续往下查。
这份记录只保留结论，过程中的日志已经随缓存目录一起清掉了。

当时的判断依据是一次全量构建的耗时，它比之后的构建明显更长。
现在回看，这个依据本身不成立，但记录保留原样，不做改写。
