## 逐条

### R01 · 版本守卫取样过晚（P1，数据丢失）

**承认的问题**：守卫取的是**写的那一刻**的版本，只保护 `stat → writeText`；真实危险窗口是
**`读 → 生成 → 写`**。单进程顺序交错即可发生，不需要多进程竞争。

**修法**：runner 按规范化路径记住「这份内容**读到时**是哪个版本」——
`stat → 读 → stat`，**两次版本相同**才算可信快照（中间被改过就不记）。写入时用**那个**版本。
三种情形：文件不存在 → `createIfAbsent`；记过版本 → `replaceIfVersion(读时版本)`；
**没读过 / 版本取不到 / `stat` 抛错 → 拒绝并落一条 `external_change` 冲突**。
最后一支是要害：以前它退化成「拿当前版本当守卫」，等于**替调用方担保一份它没读过的内容**。
截断的读也标出来（截断内容不能作为整份覆盖的依据）。

**复验**：`F01` 输出由 `{"guardEqualsHumanB":true,"humanBPreserved":false}`
变为 `{"guardEqualsHumanB":false,"humanBPreserved":true}`。
另转成 12 条永久断言（读过被改 → 拒绝且人工内容保住；没读过 → 不许覆盖；读过没改 → 正常更新；新建 → 不受影响）。

**一个我们自己踩到的坑（写下来供复验者警惕）**：第一版测试的假宿主 `stat` 收路径字符串，
而生产代码传的是 `FsTarget` 对象，类型不匹配抛出的错误**一度被当成「守卫生效」**——那次是假通过。
测试现已统一解一层并注明原因。**「测试绿」与「行为对」是两件事**，这条在本项目已经咬过三次。

### R02 · 控制提示被错误地依赖正文候选（P1）

**修法**：正文与控制提示**独立计算**，只有「正文为空**且**控制提示为空」才返回。
检查点、未命中卡、预算省略卡仍共用卡池与签名去重。**没有为了绕过返回而制造伪候选。**

**复验**：F02（空目录 + 有效检查点）与 F03（零命中 + 历史问题）的 `assembly` 由 `null` 变为含内容的文本。

### R03 · 上下文缩短后旧状态阻止重新注入（P1）

**修法**：状态集中为一个会话对象，顺序改为 **处理代次变化 → 算正文与控制提示 → 提交状态**。
一次代次转换同时重置：检索签名、卡签名、两本账、`baseline` 标记。

**诚实边界**（已写进代码注释）：判据是「消息条数下降」这条**启发式**，
**覆盖不了「条数不降的压缩」**（宿主原地改写历史、或截断后又在同一步补足条数）。
要真解决需要宿主提供可比的上下文代次标识。

**复验**：F04 由 `false` 变为 `true`。另有一组反向对照（未压缩时的相邻重复仍不重复注入、
会话之间互不影响）证明**恢复来自代次处理，不是把去重整个关掉**。

### R04 · 基线不可比时门禁放行（P2）

且它**只放行「没比成」，不豁免真退化**。补基线 schema 校验，删掉所有 `?? 0` 兜底
（缺指标曾被默认填 0，制造出假的「改善」）。

### R05 · 套件登记守卫（P2）

**说明**：这条在复审者取到的公开快照（`6b2f85b`）上确实不存在 —— 修复在**未推送**的本地提交里。
你指出的现象（放一个未登记且必抛的测试文件，`npm test` 仍全绿）在那一版上是准确的。

**修法**：`test/suite-registry-test.mjs` —— 比较磁盘上的测试清单与 `run.mjs` 的 `SUITES`，
并检查「登记了但文件不在」的空跑。`run.mjs` 与 `_` 开头的共享辅助按约定排除。

**变异验证**：从 `SUITES` 摘掉一个套件 → 该守卫红并**点名是哪个文件**；还原后哈希逐字节一致。

### R06 · 会话内去重的承诺大于实现（P2）

**处置：改说法，不改行为。** 契约原写「同一场会话里同一个问题不重复注入」，实际语义是
**相邻相同才不重复**（按会话只留一个签名）。问 A → 问 B → 再问 A，第三次会重新注入。

我们同意报告的判断：**再次要求回忆时重新给证据未必是坏行为**。因此契约里现在写清两侧：
「相邻重复不重复」是保证；「跨轮永久去重」是**明确做不到（有意）**——仅按问题字符串永久去重
会**隐藏新内容**（文件更新了却不给看）。

### R07 · baseline「整份」与截断逻辑不符（P2）

**处置：改说法，不改行为。** 契约原写 baseline「整份注入 / 完整在场」，实际它同样受单文件长度上限
（默认 1500 字符）截断，**关键内容落在尾部会看不到**。截断处会标 `…（截断）`，但那不是「完整在场」。

报告的建议（「明确为『优先注入文件头，受数量与长度限制』」）已落进契约与 README。
我们**没有**取消预算 —— 那会把一条记忆变成无上限的注入。baseline 适合放短摘要，完整正文留给工具读。

### R08 · 黑名单词元重合不能证明标注不可靠（P2）

**承认的问题**：把「无共享词元子集 = 0/68」当成「真实误注入为零」的证据是错的读法。
那个子集排除了 49/229 项检查项，而**全部 4 次真实命中都发生在这 49 项里** ——
**切片为 0 是构造出来的，不是结论。**

**修法**：主指标一律用「全部检查项」`4/71 = 5.6%`；原「标注安全子集」更名为
「**无共享词元子集**」并标注为**诊断切片**；输出里同时出现三行：主指标、切片、
以及「切片排除的检查项 49 项，其中命中 4 次」。

**材料已给过外部复审者，所以不做静默修改**：`1.0.0-eval-report.md` 文首留了显式更正记录，
写明初版错在哪。M1/M2/M3/M5 等输出块**重新运行后逐字替换**（脚本写回，不是手工改字样）。

**报告提的难负例四类**（共享常用词 / 同名不同项目 / 相同实体不同时间 / 已失效内容）已落成提案；
后三类**现有语料完全没有构造**，属于**题集扩容，不是调参能解决的**。

### R09 · 材料缺少统一候选身份（P2）

**承认的问题**：初版材料同时含 0.9.19 / 0.9.20 / D19 的声明，没有绑定单一候选，
「端到端」的说法也强于实际（材料里那条注入链走的是**手动调用注册回调 + 模拟 ctx**，
验证的是插件处理链，**不经过真实宿主注册、真实会话持久化与模型调用**）。

**修法**：
1. 本材料重出，文首「候选绑定」写明**候选提交 SHA**、各输入文件哈希、语料与问题集哈希、
   执行环境与命令。所有代码位置都指向该 SHA。
2. 测试层级在材料里分栏写清：**真实宿主实测**（探针）/ **手动回调 + 模拟 ctx** / **离线纯函数**，
   不再混着说成「端到端」。
3. 契约里「保证 / 尽力 / 已知做不到」与边界表逐条对齐，消除自相矛盾。
