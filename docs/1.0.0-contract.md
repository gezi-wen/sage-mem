# sage-mem 1.0.0 契约冻结

**这份文档只回答一个问题：升级到 1.0.0 之后，什么东西你可以依赖，什么东西不要依赖。**

写它的理由：一个功能「实现了」和「被承诺了」是两件事。所有测试都绿，也不代表某个行为
是契约 —— 它可能只是恰好如此、下次重构就被改掉。1.0.0 的意义就是把这两类**分开写明**。

**怎么用**：想依赖某个能力之前，先在下表找到它。**每一行都有编号**（`3.5` 这种），
其它文档引用它时用那个编号（边界表的 `契约` 列就是这么用的）。

## 定性只有四档（措辞固定，两份文档同一套）

| 定性 | 含义 |
|---|---|
| **保证** | 有断言支撑，而且**回归会红** —— 每次 `npm test` 与 CI 都会跑。可以依赖，改它算破坏性变更 |
| **尽力** | 设计上如此，也有实测或文档依据，但**没有会红的回归断言**，或依赖未受控的外部条件（模型行为、宿主版本、平台）。可以期待，但别写进你的架构假设 |
| **明确做不到** | 能力边界 —— 不是待修的缺陷，是取舍。别指望它，也别当 bug 报 |
| **未验证** | 我们不知道。既不能当 yes，也不能当 no |

**`断言` 列是什么**：标「保证」的行，后面写着**哪条断言在看着它** —— 格式
`套件文件名.mjs::断言名子串`，多条用 `<br>` 分隔。这不是备注，是**机器核对的输入**：

- `test/contract-binding-test.mjs` 会检查「每条保证都有标识」「标识指向的套件已登记」
  「**标识指向的断言在本次 `npm test` 里真的打出过 PASS**」；
- 写 `—` 表示这条没有断言（那它就只能标「尽力」或「未验证」）。

> ⚠️ 写标识时的两个坑：① 子串是拿**运行时的断言名原文**去匹配的，而解析器会先剥掉
> 文本里的 `**` 与反引号 —— 所以**别选一段跨过 `**` 或反引号的子串**（比如断言名是
> `` 压缩后**同题**重新开放注入 ``，就写 `重新开放注入` 而不是照抄整句）。
> ② 守卫只把 `—` 认作「没有绑定」，写「无」会被当成标识去解析然后报格式错。

**找证据**：`test/` 下的套件、`docs/decisions.md`（每个决定的理由与被驳回的方案）、
`docs/host-facts.md`（宿主实测事实）、`docs/1.0.0-boundaries.md`（逐条边界表，带与本文的对照列）、
`docs/1.0.0-eval-report.md`（量化结果）、`docs/review-findings.md`（外部复审发现的永久账）。
**本页只写结论，理由在那些文档里。**

## 6. 宿主能力缺失时的降级（实测，见 `docs/host-facts.md`）

## 7. 明确**不在**这份契约里的东西

说清「不承诺什么」和说清「承诺什么」一样重要：

- **面板 / 星图 / 设置页的界面与接口方法名** —— UI 管道，小版本里可自由变。别基于它写自动化。
- **注入文本的具体措辞** —— 见 §2。
- **内部模块的导出** —— `lib/memory/*.js` 里导出的东西是给本仓库测试用的，不是给外部用的 API。
- **性能与占用数字** —— 见 `docs/1.0.0-eval-report.md`。那些是**测量**不是**承诺**；
  机器不同结果不同。**这一条同样适用于散落在上面说明里的百分比**：
  §2.6 的 109.6%、§2.7 提到的 99.7%，都是某一台机器上某一版语料的测量。
- **宿主本身的行为** —— 我们依赖的那些事件、服务、语义都由 DSH 决定。宿主变了，我们跟着变。

## 8. 1.0.0 之后，什么算破坏性变更

按上面的定性：

- **破坏性**（必须升大版本）：改 §1–§5 里标「保证」的任何一条；改工具名或必填参数；
  去掉老格式台账的读兼容；改 `sage-mem:recall` 这个段名。
- **非破坏性**（可以走小版本）：改措辞、改排序细节、改内部状态文件格式、改面板、
  加新的环境变量、改性能。
