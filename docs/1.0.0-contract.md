# sage-mem 1.0.0 契约冻结

**这份文档只回答一个问题：升级到 1.0.0 之后，什么东西你可以依赖，什么东西不要依赖。**

写它的理由：一个功能「实现了」和「被承诺了」是两件事。所有测试都绿，也不代表某个行为
是契约 —— 它可能只是恰好如此、下次重构就被改掉。1.0.0 的意义就是把这两类**分开写明**。

**怎么用**：想依赖某个能力之前，先在下表找到它。定性只有三种：

| 定性 | 含义 |
|---|---|
| **保证** | 有断言或真实宿主实测支撑；改坏了回归会红。可以依赖，改它算破坏性变更 |
| **不保证** | 能工作，但没有硬约束；可能在小版本里变。别拿它当地基 |
| **明确做不到** | 能力边界，是取舍不是缺陷。别指望，也别当 bug 报 |

**找证据**：`test/` 下的套件、`docs/decisions.md`（每个决定的理由与被驳回的方案）、
`docs/host-facts.md`（宿主实测事实）、`docs/1.0.0-boundaries.md`（逐条边界表）、
`docs/1.0.0-eval-report.md`（量化结果）。**本页只写结论，理由在那些文档里。**

## 1. 磁盘上的记忆文件

| 事项 | 定性 | 说明 |
|---|---|---|
| 一条记忆 = 一个 `.md` 文件，YAML frontmatter + 正文 | **保证** | 这是整个插件的立身之本。你随时可以手改、用 git 管、拿别的编辑器打开 |
| 单文件上限 512 KiB（读**与**写两侧都校验） | **保证** | 超了读端拒绝、写端拒绝，两侧同一把尺子（按**字节**不是字符） |
| `description` / `type` / `tags` / `updated` / `aliases` 等字段被识别 | **保证** | 字段语义见 README |
| 未知 frontmatter 字段被忽略而不是报错 | **保证** | 你加的私有字段不会让文件读不出来 |
| frontmatter 坏掉时的降级行为 | **不保证** | 目前是「降级为不注入 + 写日志」，具体降级到什么程度可能变 |
| 记忆目录**不被写进** `last_accessed` 之类的运行时字段 | **保证** | 有断言钉住：注入一次之后记忆文件一个字节都不变。运行时状态一律在状态目录 |

## 2. 注入进上下文的东西

| 事项 | 定性 | 说明 |
|---|---|---|
| 注入内容挂在一个名为 `sage-mem:recall` 的 context 下 | **保证** | 有断言。你按这个名字找注入内容 |
| 注入文本里每条记忆以 `### <文件名>` 开头 | **保证** | 有断言 |
| 命中段落时标题带行号 `:起-止` | **保证** | 「引用可核对」靠它成立 |
| **注入内容的措辞与版式**（除了上面几条） | **不保证** | 会随版本调整，别对整段文本做字符串匹配 |
| 单场会话总预算 60 KiB，拆成正文池 + 状态卡预留（5%，夹在 1–4 KiB） | **保证** | 总上限数字不随版本变；拆法见 D16 与 `config.js` |
| ⚠️ **这个上限是软的，不是硬的** | **保证** | 实测单会话累计正文可到 **109.6%** 的正文池，**全部**来自「`baseline` 记忆被命中时整份注入且永不降级」（D9 / D16 的明确语义）。也就是说**「到顶就不再注入」这句话对 `baseline` 不成立** —— 这是有意的取舍（那类记忆的语义就是「每场会话都该完整在场」），但**别把它当成硬闸门**。超支算术见 `docs/1.0.0-eval-report.md` 3.2 节 |
| 状态卡池是硬上限 | **保证** | 实测 99.7%，未溢出 |
| 同一场会话里同一个问题**不重复注入** | **保证** | 按会话记签名，有断言 |
| 压缩 / 清空上下文后账面与去重签名归零 | **保证** | 否则恢复入口会在压缩后永久失效 |
| `baseline: true` 的记忆每场会话第一步整份注入，不吃段落替换 | **保证** | D9 / D16 |
| 到顶之后的**具体表现**（发不发状态卡、卡里说什么） | **不保证** | 目前是「正文不注、状态卡仍发」，措辞会变 |

## 3. 两个工具

| 事项 | 定性 | 说明 |
|---|---|---|
| 工具名 `search_memory` / `read_memory` | **保证** | 改名算破坏性变更 |
| `search_memory` 的必填参数是 `query`；`read_memory` 的是 `name` | **保证** | 参数 schema 是封闭的（`additionalProperties: false`） |
| 两者都**只读**，可并发调用 | **保证** | `isConcurrencySafe()` 恒 true |
| 两者都**不抛异常**，失败返回结构化错误 | **保证** | 有断言；工具抛出去会打断模型那一轮 |
| `read_memory` 带过期 `revision` 时**不返回内容** | **保证** | 只回 `revision_changed`；否则调用方会拿过期行号读错东西 |
| 两者走**同一条**安全读路径（文件名检查 → 符号链接与保留名身份 → 体积闸门） | **保证** | 没有为工具另开绕过闸门的入口 |
| `search_memory` 的 `coverage` 如实上报「有几段因相关性不够被滤掉」 | **保证** | 「不够格」与「记忆里没有」是两件事，混在一起会得出相反结论 |
| 搜索结果**语义召回** | **明确做不到** | 纯词法匹配。提问与原文没有任何词面重合时召不回；同义改写用 `aliases` 补 |
| 返回条数的具体排序细节 | **不保证** | 分数会随排序算法调整 |

## 4. 状态目录（`<记忆目录的上一层>/.sage-mem/`）

| 文件 | 定性 | 说明 |
|---|---|---|
| `access.json`（访问台账，v2：`injected` / `read` / `use` / `readRev`） | **保证** | **v1 的老格式读端仍然兼容**，写端一律写 v2 |
| 台账**参与检索排序** | **明确做不到（有意）** | D3：只记不排。「被注入」「被主动读」「被采用」含义不同，混成一个热度就再也分不开 |
| `tasks/<任务 id>/WORKING.md`（任务检查点） | **保证** | 存在时注入末尾给一条短句柄 |
| `conflicts/<id>.json`（冲突队列） | **保证** | 文件格式与状态机被断言 |
| **自动裁决冲突** | **明确做不到（有意）** | 保留哪边由人决定。静默重试与静默放弃都是在替你决定 |
| `locked.json` / `reserved.json` / `autodream.json` / `settings.json` | **不保证** | 内部状态，格式可能在小版本里变。`dream.json` 是待迁移的旧名 |
| 状态目录里除上述之外的文件 | **不保证** | 别依赖内部文件名 |

## 5. 配置与环境变量

| 变量 | 默认 | 定性 |
|---|---|---|
| `SAGE_MEM_DIR` | `~/.sage-mem/memory` | **保证** |
| `SAGE_MEM_STATE_DIR` | `<记忆目录的上一层>/.sage-mem` | **保证** |
| `SAGE_MEM_MAX_SESSION_BYTES` | 61440（60 KiB），夹在 4096– | **保证** |
| `SAGE_MEM_MAX_RESULTS` | 10（1–30） | **保证** |
| `SAGE_MEM_MAX_CHARS` | 1500（200–20000） | **保证** |
| `SAGE_MEM_MAX_BASELINE` | 8（1–50） | **保证** |
| `SAGE_MEM_STALE_DAYS` | 1（0–365） | **保证** |
| `SAGE_MEM_TASK_ID` | 空（回落会话 id） | **保证** |
| `SAGE_MEM_DEBUG` | 关 | **不保证**（调试开关） |
| 设置页面板里的值 | — | **不保证**：某些项要重启 DSH 才生效，具体哪些以面板文案为准 |

## 6. 宿主能力缺失时的降级（实测，见 `docs/host-facts.md`）

这是最容易被人当成「保证」、实际只是「尽力」的一块，所以单独列。

| 缺什么 | 行为 | 定性 |
|---|---|---|
| 宿主没有 `tools` 服务 | 两个工具不注册；**记忆注入照常**，状态卡换成「直接读记忆目录」的文案 | **保证** |
| 宿主没有 `fs` 服务 | 写门不生效；autodream 回落到自己的原子写 | **保证**（有断言） |
| 宿主没有 `tools/result` 事件 | 观测不到「模型主动读了什么」；台账只有 `injected` | **保证** |
| `pwsh` / `bash` 里读改记忆 | **认不出来**，不记入台账 | **明确做不到**（有意的克制：认不准就不认，免得误记成事实） |
| 写门只对**工具发起**的写入生效 | 模型用内置 `write` / `edit` 改记忆会被版本守卫拦；插件自己的写入不走这条 | **保证**（实测：插件自己写时事件 0 次） |
| `web` / `desktop` profile 上的行为 | 探针**从没在这两个 profile 上跑过** | **不保证**（未验证） |

## 7. 明确**不在**这份契约里的东西

说清「不承诺什么」和说清「承诺什么」一样重要：

- **面板 / 星图 / 设置页的界面与接口方法名** —— UI 管道，小版本里可自由变。别基于它写自动化。
- **注入文本的具体措辞** —— 见 §2。
- **内部模块的导出** —— `lib/memory/*.js` 里导出的东西是给本仓库测试用的，不是给外部用的 API。
- **性能数字** —— 见 `docs/1.0.0-eval-report.md`。那些是**测量**不是**承诺**；机器不同结果不同。
- **宿主本身的行为** —— 我们依赖的那些事件、服务、语义都由 DSH 决定。宿主变了，我们跟着变。

## 8. 1.0.0 之后，什么算破坏性变更

按上面的定性：

- **破坏性**（必须升大版本）：改 §1–§5 里标「保证」的任何一条；改工具名或必填参数；
  去掉老格式台账的读兼容；改 `sage-mem:recall` 这个段名。
- **非破坏性**（可以走小版本）：改措辞、改排序细节、改内部状态文件格式、改面板、
  加新的环境变量、改性能。

## 附：这份文档自己的边界

- 「**保证**」的依据是**本仓库的断言与实测**，不是形式化证明。断言可能测错东西 ——
  0.9.17 / 0.9.18 就有两个套件**漏登记**、从来没跑过（已更正）。所以「有断言」这句话本身
  也需要被审查，而不是被信任。
- 标「**不保证**」的条目里，有些其实是稳定的、只是我们还没决定要不要承诺它。
  审查时如果你希望某条升级为「保证」，说一声 —— 那需要的是一条断言，不是一句说明。
