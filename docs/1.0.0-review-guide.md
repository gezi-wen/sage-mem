# 1.0.0 复审材料包 · 入口

**给审查者**：这个仓库是一个 DSH 插件的 1.0.0 候选版本。你大概没有它的上下文，
所以这份入口只做三件事：**读什么、按什么顺序读、以及我们最希望你挑战哪里**。

| 顺序 | 文件 | 它回答什么 |

- `decisions.md` —— 每个设计决定的理由**与被驳回的方案**。想知道「为什么不那样做」看这里。
- `host-facts.md` —— 宿主契约的**实测**事实（不是文档推的）。含我们踩过的坑与没能验证的部分。

## 最希望你挑战的六处

材料里写得最顺的地方，往往是最该被怀疑的地方。这六处是我们自己知道的薄弱点：

1. **「保证」是不是真的被断言咬住了。** 上一轮我们被指出五条「承诺与事实对不上」——
   代码在那些点上压根没被断言碰过，而契约、README、CHANGELOG 三处都写着承诺。
   现在契约每条「保证」都带一个断言标识（`套件::断言名子串`），由
   `test/contract-binding-test.mjs` 机器核对「**这条断言在本次运行里真的打出过 PASS**」。
   **请专压这个机制本身**：随便挑三条绑了断言的「保证」，把断言删掉或改坏，跑 `npm test`
   看是否变红、变红时是否点得出是哪一行。**改坏了却全绿，就说明这套机制是摆设。**
   另外请检查：有没有**该降级却没降级**的行 —— 我们按这条规矩降了 4 行、拆了 3 行，
   清单在 `CHANGELOG.md`，判断是否合理是我们的口径，不是技术事实。

2. **断言测的是不是它自己。** 我们的「保证」= 有断言或实测支撑，**不是形式化证明**。
   而断言可能测错东西 —— 这个项目**已经真实翻过两次车**：两个版本、126 条断言
   从没被运行过，而两版更新日志都写着「全绿」。请对每一条「保证」追问：
   **这条断言测的是它本身吗？还是测了一个长得像它的东西？**
   （已知的两处：6.7 写门在真实宿主里的**到达性**没有回归断言；6.8 的支撑断言跑在**合成观测**上。）

3. **性能与召回数字的可迁移性。** 评测语料只有 30 份，且它的 `description` 是**为了让检索能命中而手写的** ——
   真实使用里摘要往往随意甚至缺失。我们认为可迁移的是**相对关系**（某些设计 A 明显优于 B），
   不可迁移的是**绝对值**。请专门压这个区分：**哪些结论换个语料就没了？**

4. **单点测量被当成对照的地方。** 材料里凡标「反向对照」的都是真的开/关对照过；
   凡标「单点测量」的意思是——**没有对照，别信它的因果**。请扫一遍看有没有漏标的。
   2026-10-16 我们主动把两处**测量**从契约里挪走了（109.6% 的软上限、99.7% 的卡池占用），
   但可能还有 —— 尤其那些写成「实测 X%」的句子。

5. **两份文档的一致性机制有没有漏洞。** 上一轮你（或上一位复审者）抓到边界表把「事件注册窗口」
   标成 best effort、而契约正文别处写成保证。现在边界表有 `契约` 对照列、由
   `test/doc-consistency-test.mjs` 逐行核对定性相同。**但对照表是人写的** ——
   请检查：有没有**该对上却没写对照**的行（我们用 `—` 表示「契约里没有对应行」，
   这个 `—` 用得对不对？有没有明明有对应却标 `—` 来躲开检查的？）

6. **真实宿主实测的覆盖面不对称。** 探针**插件**只在 headless profile 上跑过；
   桌面版只跑过 Inspect 查询（读契约声明，另一条路径，**验不到「事件会不会到达」**）；
   网页版**两条都没有**。这条在边界表里标为「未验证」，但它可能影响前面所有结论的适用范围 ——
   尤其「事件到达性」那类结论，换个 profile 未必一样。**2026-10-16 我们还确认了桌面侧更难**：
   `dsh --profile desktop` 连只读的 `--dump-config` 都被 Electron 拒绝。

## 怎么独立复核（不需要我们这个环境）

```bash
npm test                     # 全部断言。含三条守卫：套件登记 / 契约↔断言 / 文档一致（含 README 徽章）
node test/contract-binding-test.mjs   # 只跑「保证 ↔ 断言」那条（单独跑会自己补跑需要的套件）
node scripts/eval-retrieval.mjs --mode all --baseline test/eval/baseline.json
node scripts/host-facts-probe.mjs     # 需要在 DSH 宿主里跑；文件头写了怎么挂
```

第三、四条分别要 DSH 宿主或较长时间；前两条纯 Node 即可。
`npm test` 里那两条文档守卫吃的是**本次运行落的断言台账**（`test/_passlog.mjs`），
所以它们排在套件名单最后 —— 单独跑时会退化成自己补跑那几个套件。

## 材料的局限（先说清，免得你按它推出来的结论比它能支撑的更远）

- **它是我们自己写的。** 写材料的人和写代码的人是同一批，所以它天然倾向于把我们的取舍
  写得比实际更合理。请优先怀疑「**取舍理由**」，那是最容易自我美化的一段。
- **它不完整。** 契约里每条「保证」现在都有断言指着（有守卫），但**边界表没有**同类的
  「该进表的都进了」守卫 —— 38 行之外还有没有该列的能力，仍然靠人。这和「套件登记守卫」
  是同一类问题，只是**这次仍然没有守卫**。
- **数字会过时。** 评测报告的口径是本版本。代码一改，绝对值就旧了；相对关系通常还在。
- **`docs/` 下的其余文档不是这份材料的一部分** —— 它们是开发过程中的记录，风格与时效性都不同
  （其中 `host-facts.md` 已发现一处与代码矛盾的旧句子，见边界表「表外说明」）。
