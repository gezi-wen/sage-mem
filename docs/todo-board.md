# 待办清单看板（2.11.1 · 实验性；2.15.0 收尾）

右侧栏的一个页签：把记忆目录里的 `project_session-state.md`（跨会话代办清单）画成分组卡片，可勾选、可新增、可编辑。**默认关闭**，开关在 设置 → 记忆管理 → 实验性。

## 三条前提

1. **文件是唯一真相。** 看板不建自己的存储、不缓存草稿：读的是那个 markdown，写的是那个 markdown。AI 用普通编辑工具改它，看板 4 秒内跟上（按 `revision` 比对，内容没变就不重渲染）。
2. **只做行级手术。** 勾选 = 把那一行从原组删掉、追加到「已完成，待删除」块；新增 = 在那组最后一条后面插一行；编辑 = 替换那一行；删除 / 清空 = 删掉那几行。frontmatter、引用块、空行、别的节一个字节都不动。
3. **看板只搬家，不代写留档。** 完成项被搬进「已完成，待删除」块就停在那里 —— 把它写进 `session-log.md`、再从这份清单里删掉，是 **agent 的活**（下次读写这个文件、或会话收尾时做）。看板不替 agent 判断哪条值得留。
   **2.15.0 的例外是用户自己按的那一颗按钮**：待删除块头上的「搬进流水」会代做同一件事（见第四节）。两者的关系是「谁都可以做，但别做两遍」—— 流水里已有的正文会被跳过。

## 2.15.0 新增的四件事

| 能力 | 落点 | 为什么不那样做 |
|---|---|---|
| **筛选**「未完成 / 全部」 | 页签第二行；默认未完成 | 不持久化：持久化会把「上次点了全部」变成永久视图，与「默认只看没做完的」矛盾。**待删除块不受筛选影响** —— 它是待清空的队列 |
| **撤销 3–5 步可配**（默认 5） | 第二行的选择器 | 只把「几步」的偏好写 `localStorage`，**栈仍只在内存**：落盘要一起设计并发、清理与跨设备一致性 |
| **组展开记忆** | 按**节标题**存 `localStorage` | 不按序号：编辑文件后序号会错位。「全部展开 / 收起」**不写偏好**（一次性动作，写了就永远全展开） |
| **检查点聚合（只读）** | 清单上方的虚线块 | 不合并写入：那些文件有自己的 `revision` 与写协议（`writeCheckpoint`），看板不是它们的作者 |

### 「搬进流水」的确切行为

1. 读 `session-log.md`（保留名，走 `memory/readRaw`）；文件不存在就当空文件起头。
2. 按**正文归一化**（连续空白压成一个空格）比对流水里已有的行，**只写没记过的**；一条新的都没有就跳过第一次写盘。
3. 追加格式：`## <YYYY-MM-DD HH:mm> · 待办收尾（N 条）` + 来源行 + 逐条 `- <正文>`；正文**照抄**。
4. 写 `session-log.md`（带 `expectedRevision`），**成功之后**才写清单（删那几行，也带 `expectedRevision`）。
5. 两个失败分支都明说：清单 `stale_revision` → 流水已写、清单没删，刷新后再点一次（重复会被跳过）；别处的错 → 原样报出来。

**顺序不能换**：先删清单再写流水的话，第二步失败就真丢条目。**这一步不可撤销**（流水那半撤不回来），所以搬完清空撤销栈。

### 检查点聚合的边界

- 只读 `<状态根>/tasks/<taskId>/WORKING.md` 的「未完成」节（`checkpoint.js` 的 `itemsOf`，与注入链同一份判据）。
- 最多 12 个任务 × 每任务 20 条；超出返回 `truncated`，面板仍是只读提示。
- **读不出骨架的检查点不显示**（`malformedReason` 非空）—— 与 `readCheckpoint` 同一条判据：读不出来的东西比读不到更危险。
- 目录里没有 `WORKING.md`、或单个文件读失败：跳过那一条，不拖垮整块。
- 老宿主没有 `memory/checkpoints` 时，整块不出现（不是显示空壳）。

## 认的文件形状

```markdown
---
name: session-state          # frontmatter 原样保留，不解析
---
# 标题
> 说明引用块

## ⏳ 等你一句话             # 每个 ## 是一组
- **标题**（指针）。正文……   # `- ` 开头是一张卡；`**…**` 是标题，其余是正文
- [x] **旧文件里的已完成** —— 2.11.0 及更早的写法，照旧识别
  - 缩进的行并进上一条显示（不算新条目）

## 长期约束（不是待办，别删）  # 标题含「长期约束 / 不是待办 / 别删」→ 默认收起

## 已完成，待删除             # 标题含「已完成 / 待删除」→ 这是搬家的落点
- [x] **做完的一条** —— 正文
```

- 没有 `##` 的文件：所有条目落进一个兜底组（标题显示「未分节」）。
- 没有 `**…**` 的条目：不画标题行，正文自己说话。
- CRLF 文件读得懂；新建的块按文件原有的换行写（不制造一份两种换行），改动行本身仍归一为原文件的行尾。
- 「已完成，待删除」块**可以不存在**：第一次勾选时看板在文件末尾追加 `\n## 已完成，待删除\n` 再写条目，其余字节不动。

## 交互与错误形态

| 动作 | 落盘 | 失败时 |
|---|---|---|
| 勾选 | 从原组**删掉那一行**，在「已完成，待删除」块末尾追加 `- [x] <原正文>`（正文不带原行首 `- `、不带已有 `[x]`） | `stale_revision` → 提示「文件刚被别处改过，已重新加载」，**不覆盖** |
| 取消完成 | 反向搬家：从待删除块删掉，回到它**原来所在组的末尾**（原组只在内存里记着；记不住就退到第一个普通组，全篇没有普通组时退到文件末尾） | 同上 |
| 逐条删除 | 删掉待删除块里那一行（只在待删除块里有这个按钮） | 同上 |
| 清空全部 | 删掉待删除块内**全部条目行**，`## 标题` 留着（块还要接下一次勾选） | 计数为 0 时不写盘 |
| 新增 | 该组末条之后插 `- <文本>`（待删除块不给「加一条」：那一块只能由勾选搬进来） | 同上；空白内容不写 |
| 编辑 | 替换该行正文（保留 `[x]`） | 同上 |
| 撤销 / 重做 | 写回历史快照，**两步**；任何新写入都清空重做栈 | 只在内存里，关页面即失效 |

- **谁来删**：待删除块是队列不是结论。agent 在**下次读写这个文件**或**会话收尾写 `session-log.md`** 时，把里面的条目搬进流水留档、再从 `project_session_state.md` 删掉 —— 别让它长期堆积。**绝不自行删掉「已完成，待删除」以外、用户没勾选的条目。**
- 陈旧宿主（装着旧 manifest 的进程）：写入会降级重试，成功后提示「这次写入没有版本校验，请确认内容正确」。
- 文件不存在：显示「没找到 project_session-state.md」，**不代建** —— 免得造出缺 frontmatter 的文件。
- 旧文件里的 `- [x]` 条目：普通组里照旧识别（读得懂旧写法），只是看板不再生产它 —— 再勾一次才会把它搬进待删除块。

## 为什么这样承载

- 走**官方** `sidebarRightTabs` 注册表：`register({ id, kind, title, guide })` + 键控槽 `sidebar.right.pane.tab` / `sidebar.right.pane.tab.title`。`guide` 条目让「开始」页自动长出卡片（better-sidebar 从同一张表读）。
- **definition + body 常驻，只随开关换 guide**：关掉开关时已打开的页签不会变成孤儿，它切到「已关闭」态；再打开时不需要刷新页面。
- 不新增 remote：`memory/readFile` 回 `{ content, revision }`，`memory/writeFile` 带 `expectedRevision` 做 CAS —— 并发冲突由宿主判定，客户端只负责重读。
- **勾选为什么是搬家而不是加 `[x]`**（2.11.1）：完成项留在原组里，原组就越读越长，而「已完成」本来只是**待清理的队列**。搬到单独一块之后，谁该搬进流水、搬完该删哪几条，人和 agent 看到的是同一个显式位置。
