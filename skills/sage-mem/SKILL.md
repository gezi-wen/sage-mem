# sage-mem 使用指南

记忆不是存档，是**给未来的自己留的可用证据**。每次会话开始你什么都不记得；写进来的每一条都要让下一个你真的能在三十秒内判断「这条还准不准、能不能用」。

本技能管「怎么用这个插件」：文件长什么样、四类怎么分、什么坚决不写、写完怎么验、检索不到时先查哪里。

---

## 一、它给你什么

三件事，别的没有：

1. **自动注入** —— 每次提问，它按问题检索记忆、把相关片段塞进系统提示词，你直接「想起」。
2. **两个工具** —— `search_memory`（按词找）与 `read_memory`（按文件名读，可翻页）。
3. **纯文件** —— 没有数据库、没有常驻进程。所有记忆都是目录里的 `.md`，你能用普通文件工具直接读写、diff、放进 git。

**没有**「写入工具」。要写记忆，用你手上的通用文件写入工具改 markdown。格式错了不会被拦，只会在下次注入时表现为「这条永远搜不到」。

---

## 二、记忆长什么样

一条记忆 = **一个 `.md` 文件 + YAML frontmatter**。

```markdown
---
name: deploy-freeze
description: 生产环境在发版窗口内禁止合并；窗口是每周三 10:00-12:00。问「能不能合」「发版时间」时用。
metadata:
  type: project
---

# 发版冻结窗口

正文……
```

- `name`：稳定标识（小写、连字符），改名等于换一条记忆。
- `description`：**最重要的一行**，检索主要靠它（见第八节）。
- `metadata.type`：四类之一（见第三节）。
- 正文：随便写，但**前 1500 字以外基本不会被注入**，硬货放前面。

文件名同样参与检索打分，所以文件名要有实义词：`feedback_dangerous-ops.md` 远好于 `feedback_f1.md`。

## 三、四类记忆：决定你写进哪个文件

| 类型 | 存什么 | 判据 | 例子 |
|---|---|---|---|
| `user` | **用户是谁**：身份、偏好、习惯、长期约束 | 换成任何人都会变 → 不是它 | 「用中文」「不吃香菜」「惯用 Windows」 |
| `feedback` | **用户给的工作方式**：纠正、规矩、踩过的坑 | 「以后遇到 X 就按 Y 做」 | 「发布前必须脱敏四查」「别用 git push --force」 |
| `project` | **进行中的工作**：目标、状态、决定、待办 | 有生命周期，做完就该更新或归档 | 「迁移项目的当前进度」「这个功能的三个待办」 |
| `reference` | **外部信息在哪找**：地址、凭据位置、指针 | 「怎么找到它」而不是「它是什么」 | 「服务器地址见某文件」「API 文档在某个 URL」 |

**分类不是装饰**：`type` 会进检索词表，也会影响使用者怎么看这批记忆。归错类的代价是「该被当规矩的一条，被当成背景资料」。

**一条记忆只放一件事。** 主题不同的东西写两个文件 —— 混在一起会让检索命中它却只给半截，也会让「改其中一件」变成「改整份」。

---

## 四、什么不写

这条比「写什么」更能决定记忆库的好坏。**一条坏记忆的代价不是占空间，是让未来的你在错误的前提上做判断。**

- **读代码 / 跑一次命令就能得到的** —— 比如「这个函数在第 120 行」。行号会漂，漂了还看起来很权威。存**推不出来的那一点**：为什么这么设计、当时否决了什么。
- **会过期的状态快照** —— 「当前版本 2.1.22」。要存就存成「怎么查当前版本」，或者明确标注日期并当作历史。
- **一次性的中间过程** —— 调试时的临时假设、试错路径。除非结论有价值，否则不要留过程。
- **从别处抄来的通用知识** —— 那是文档的活。记忆存的是**这个项目/这个人特有的**东西。
- **未经核实的推断** —— 把猜测写成事实，下一个人会拿它当依据。宁可写「未验证：怀疑是 X 因为 Y」。

**判据一句话**：下一个你读到这条，是**省一轮核实**，还是**多一次误判**？后者就删掉。

## 五、写一条记忆的流程

1. **先搜**：`search_memory` 看有没有相关的。有就**改它**，别再开一个 —— 同一件事两份，迟早分叉。
2. **定类型**：按第三节的表。
3. **定文件名**：`<类型>_<实义词>.md`，如 `feedback_release-steps.md`。
4. **写 frontmatter**（字段见第六节），description 按「将来我会怎么问」来写。
5. **写正文**：结论在前，理由在后，风险写清楚。
6. **更新 `updated:` 到今天就改（如果字段存在）** —— 注入时会显示「保存于 N 天前」，不改就永远显示旧日期，未来的你会误判它过期。
7. **验证**：跑 `frontmatter-assert`（见第九节）。
8. **索引**：如果目录里有 `MEMORY.md`，给它加一行（见第七节）。

## 六、frontmatter 的硬格式

```yaml
---
name: <稳定标识，与文件名不同也无妨，但别改>
description: <一行，写清「什么时候该用它」>
metadata:
  type: user | feedback | project | reference
  updated: 2026-01-01        # 可选但强烈建议
---
```

**两个静默杀手**（不会报错，只会让检索面残缺）：

1. **值里有空格或 `#` 却没加引号** —— `description: 部署 注意 # 危险` 里 `# 危险` 会被当注释吞掉。含空格、冒号、`#`、单双引号时**整值加引号**：`description: "部署 注意 # 危险"`。
2. **缩进错位** —— `metadata` 下面的 `type` 必须缩进两格。缩进错会让 YAML 解析出一层多余结构，`type` 变成空。

**可选检索字段**：如果插件版本支持，`aliases`（同义说法）与 `baselinePriority`（每场会话必带的优先级）能显著提升命中率。不确定支持与否时，先搜一下同类记忆的实际写法，别凭空发明字段。

## 七、索引与归档

**`MEMORY.md`（索引）** —— 如果记忆目录里有它，它就是把散落文件串起来的那张表：按类型分组，每条一行「链接 + 一句话」。**新增/改名/删除记忆时同步它**，否则索引会指向不存在的文件（断链）。

索引是**整份覆盖风险最高**的文件：永远用「改一行」而不是「重建全文」，否则原有内容一个字都留不下。

**归档** —— 不再成立但还有历史价值的记忆（被取代的决定、已完成的阶段），移进 `archive/` 子目录。

- 归档的语义是「**还在，但不该进上下文**」：检索不扫子目录，所以归档 = 静默失效且可回退。
- **别直接删**。删了就没人能回答「当时为什么那么决定」。

---

## 八、检索怎么工作（以及为什么你搜不到）

**命中靠词面重合，不靠语义。** 机制：把提问和「每条记忆的 description + 文件名」都切成双字组，算覆盖率，按得分取前若干条。

推论，写记忆时照着做：

- **description 要写「将来会怎么问它」**，不是「它是什么」。一条讲归档的，description 里要有「归档」「索引」「断链」这些字 —— 用同义词或缩写就是错过。
- **文件名要有实义词**，它和 description 一起打分。
- **改内容顺手改 `updated:`**，否则新鲜度标记会骗人。

**上限不是写死的数字。** 一次注几条、每条多少字、单会话总预算、单文件上限 —— 这些随版本和用户设置变。插件在注入时会带上当前生效的值；**以注入文本为准，别把数字抄进记忆，也别硬编码**。

## 九、验证

两个随包脚本（在技能的 `scripts/` 下）：

```bash
# 单条/多条记忆的 frontmatter 断言：真有块、真能 YAML 解析、name/description/type 非空、
# 以及「未加引号的值里有空格+#」这个静默杀手
node <技能目录>/scripts/frontmatter-assert.cjs <记忆文件.md> [更多文件...]

# 记忆库体检：索引断链、分类配比、整理阈值提醒
node <技能目录>/scripts/memory-audit.cjs [记忆目录]
```

**退出码 0 = 通过，非 0 = 有硬问题。** 别靠眼睛看 —— 落盘之后必须当场验。

## 十、症状 → 先查哪里

| 症状 | 先查 |
|---|---|
| 明明写过的记忆搜不到 | description 里有没有「你提问时会出现的词」；文件是不是在记忆根目录（子目录不扫） |
| 记忆写进去了但注入的是旧的 | 有 `updated:` 就把它改对；没有就检查文件 mtime |
| 改了文件名之后一切都不对 | 记忆的身份是文件名 + `name`；索引与双链都指向旧名，要一起改 |
| 索引里一堆断了 | 跑 `memory-audit` 的断链检查；归档文件要去 `archive/` 下找 |
| frontmatter 看着对但解析出来是空的 | 未加引号的 `#` 把后半句吞了；或者缩进错位 |
| 注入总量很快就到顶 | 记忆太啰嗦 —— 每条的精炼度直接决定能注几条 |

---

## 十一、边界

- **改的是记忆内容** → 本技能。
- **改的是插件本身**（注入逻辑、检索算法、索引生成）→ 那是代码问题，去读插件仓库的 `lib/`，不是改记忆能修的。
- **记忆目录由谁决定** → 环境变量 `SAGE_MEM_DIR`（插件读它）。不确定当前用哪个目录时，看设置页，或读一次 `search_memory` 返回的 `file` 字段路径。
